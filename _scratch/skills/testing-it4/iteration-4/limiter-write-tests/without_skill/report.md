# Limiter test suite

Wrote `limiter_test.go`: 13 tests covering New's panics, full-at-start bucket, burst-0 Allow/Wait semantics, Wait consume/block/cancel/deadline paths, ErrClosed after Close (including with tokens still buffered), Close unblocking waiters and idempotency, refill restore and burst capping, plus a concurrent Allow/Wait/Close stress test for the race detector. Timing-sensitive tests use slow (1s) refill intervals for determinism or poll with generous deadlines to avoid flakiness.
Findings for the author: (1) `Wait` does not check `ctx.Done()` before racing the token select, so a call with an already-cancelled context can still succeed when a token is buffered (`x/time/rate` checks ctx first) — outcome is nondeterministic, so I did not pin it in a test; (2) `New` with rate > 1e9 yields a zero interval and `time.NewTicker` panics inside the refill goroutine, crashing the process (untestable via recover); (3) `Allow` still hands out buffered tokens after `Close`, which is inconsistent with `Wait`'s ErrClosed but not forbidden by its doc.
Final status: `go build ./...` clean, `go vet ./...` clean, `go test -race -count=1/3` and `go test -count=5` all pass. No deliberate failing tests.
