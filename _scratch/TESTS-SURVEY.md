== DOCTRINE ==

1. A test name is a claim about the contract, not a pointer to a symbol. Type-with-methods APIs get behavior sentences (TestSeededHash, TestCopyPriority, TestMultiReaderFinalEOF, TestNoonIs12PM); pure-function APIs may name the function but delegate to a shared runner covering the whole family. If you can't state what breaks when the test fails, the test is misnamed.
2. Aspire to one test exercising the API the way a user composes it: TestGolden (crc32) = tables+constructors+writes+sums+misalignment; TestHashGrouping (maphash) = all write paths must agree. The unit of testing is an invariant, not a function.
3. Doc comments are the test plan. Every subtle assertion in these packages traces to a doc sentence (hash.Hash's "It never returns an error" -> WriteWithoutError; Builder's "Do not copy" -> TestBuilderCopyPanic; fnv's "big-endian" -> testIntegrity). Conversely, when a test checks something non-obvious, the contract is restated in prose right above it (io/multi_test.go style).
4. Ship conformance kits for interfaces you own; implementations buy the whole documented contract in one line (internal/testhash.TestHash, testing/iotest.TestReader, testing/fstest.TestFS). Subtests named after doc clauses. Floor: compile-time var _ Iface = &T{}.
5. Serialized representations that users persist are contract: pin them byte-exact inline (halfState strings, hash/marshal_test.go hex goldens, time's MarshalBinaryVersion2 tests). A maintainer changing the format MUST edit a golden — that friction is the feature.
6. Goldens come from an independent oracle (test_gen.awk + reference binary; simpleIndex; simpleMakeTable), inputs from one shared corpus; alternate implementations are cross-checked against each other on adversarial lengths, not given separate golden sets.
7. Tables for input->output mappings; bespoke scenarios for interactions. io/multi_test.go has no tables at all. When cases are heterogeneous behaviors, the table holds closures (TestBuilderCopyPanic). Case-ID appears in every failure message so plain loops beat t.Run ceremony for small goldens.
8. Test from package foo_test (the user's seat); punch the minimum peephole back in via export_test.go: error sentinels (io), introspection of chosen strategy (strings PrintTrie/DumpTables), state-reset hooks suffixed ForTesting (time). Drop to the internal package only to cross-check implementation kernels (crc32 simple/slicing/arch) or private fields (maphash seed).
9. Documented performance is contract: AllocsPerRun with exact wanted counts, mallocs counting, GC-liveness, call-depth flattening. Pin panic/error TEXT only where users programmatically or visually depend on it.
10. Regression tests get promoted to property claims; the issue number lives in a comment ("issue 16795", "See issue 34925"), never in the name.
11. Deliberate non-testing is visible: symbols sharing a kernel go untested directly (crc64.Update); properties that do NOT hold are kept as commented-out assertions with the reason (TestCaseConsistency); ranges outside the promise are carved out in-line ("// not required to work"); host-machine state is excluded by hermetic fixtures; long statistical batteries are gated (-race build tag, testing.Short()).
12. Examples carry trivial assertions AND the hardest usage instruction, compile+run under go test, and their doc comments never open with the function name — they read "This example uses a Decoder to decode a stream..." (encoding/json/example_test.go). Package-level Example() narrates the zero-value contract (maphash); whole-file examples demonstrate a real use case (example_bloom_test.go).
13. Randomness is disciplined: log the seed for replay (testhash), fixed seeds for corpora (smhasher rand.NewSource(1234)), quick.Check for round-trips. Order-dependent initialization is declared ("First test, so that it can be the one to initialize castagnoliTable", crc32_test.go:18).

### Recommendations

- Adopt the naming rule repo-wide: a committed test's name states the contract claim a maintainer would break (TestUnitRoundTrip, TestDiagnosticsStable, TestSymbolBindingStages), never the function it happens to call; if the SDL compiler grows per-function TestParseX/TestLowerY tests, fold them into one golden-driven pipeline test the way crc32's TestGolden folds five symbols into one workflow.
- Treat the intermediate representation the way hash/ treats marshaled state: it is persisted and reconciled by deployment environments, so pin it byte-exact. Write one TestGoldenIR over a corpus of .sdl definitions with expected IR inline (or in testdata/), with a header comment copied in spirit from hash/marshal_test.go: 'lock in the current representations'. Any breaking IR change must force a golden amendment in the same commit.
- Promote solution/sample.sdl into the shared test corpus role that hash/test_cases.txt plays: every compiler stage (parse, bind, lower, vet, lsp) exercises the same corpus, so one new concept added to the mockup automatically confronts all stages.
- Build a one-line conformance kit for any interface the catalogue or reconciler defines (internal/testcatalogue.TestCitizen(t, factory) style), with subtests named after the doc-comment clauses of the interface, mirroring internal/testhash.TestHash's SumAppend/WriteWithoutError/ResetState naming. Every implementation, including future ones, buys the whole documented contract in one call.
- Write committed tests from package foo_test exclusively (the user's seat); when internals must be observed, add a minimal export_test.go: error sentinels (io pattern) or which-strategy introspection (strings PrintTrie pattern) or state-reset hooks suffixed ForTesting (time pattern). Never widen the real API for tests.
- Since cmd/sdl is a CLI, resist testing the built artifact: test the packages the verbs delegate to, as their sibling users. Pin diagnostic/error TEXT only where a user or the lsp client acts on it (time's TestNotGobEncodableTime pins err.Error(); maphash pins the panic string).
- Convert trivial assertions into Examples on the exported API, one per tricky concept rather than per function; give the hardest usage instruction (e.g., staged symbol binding order, catalogue admission) an ExampleX with real Output like crc32's ExampleMakeTable teaches reversed polynomial notation. Example doc comments must not open with the function name — write 'This example compiles a definition against ...'.
- When a regression is fixed, commit the probe renamed as the property it protects, with the issue reference demoted to a comment ('This used to yield bytes forever; issue 16795.'); throwaway bug probes, build-tagged experiments, and scaffold mains stay uncommitted per the io/time precedent that only contract-bearing tests land.
- Prefer bespoke 3-line fakes over frameworks for interaction contracts (io's byteAndEOFReader, writeToChecker, method-hiding embed): for reconciliation, a fake environment that misbehaves in exactly one documented way per test will cover more contract than any mock library.
- Document deliberate non-testing where it will be found: symbols sharing a kernel need no direct test (crc64 never calls Update/Checksum); properties that intentionally do NOT hold belong as commented-out assertions with the reason (strings TestCaseConsistency); host-dependent state gets hermetic fixtures (time's GOROOT-only tzdata) — for us, tests must not depend on a developer's local catalogue or environment.

## Design moves that make a package testable
- One-interface behavior slots consumed identically by users and tests: http.Handler, http.RoundTripper, driver.Connector (database/sql tests run an entire fake in-memory DB behind it), slog.Handler, fs.FS, io.Reader/Writer.
- Injection of the boundary object, not a flag: http.Server.Serve(net.Listener) accepts any listener; Transport.DialContext/DialTLSContext accept any dial func — so httptest swaps the whole network for nettest conns without the production package knowing.
- Lifecycle hooks as seams: http.Server.ConnState lets httptest track conns for graceful Close; database/sql has putConnHook (test-only var assigned in _test init) to catch double-free.
- Test-only exports via export_test.go: http2's cc.TestSetNetConn(cli) replaces the (possibly TLS) conn under an already-constructed client.
- NO clock injection anywhere: stdlib rejected threading clock interfaces through APIs and instead virtualized time in the runtime (synctest). Pre-synctest poll-with-deadline loops survive only in benchmarks ("We don't use synctest in benchmarks, so just poll" — sql_test.go:352).
- Bubble-compatible fakes block on channels, never mutexes: net/http's fakeNetListener implements lock()/unlock() with a channel pair (netconn_test.go:44-58).

## Harness API shape rules (httptest as canon)
- Entry point takes testing.TB, registers t.Cleanup, converts panics to test failures, routes internal logs to t.Logf (testLogWriter, clientserver_test.go:352).
- Documented configuration window: "must not be changed after the first call to Client, Start, or StartTLS" — mutation-then-freeze, enforced by panic.
- Offer two altitudes: in-memory end-to-end (Server) and pure in-process (ResponseRecorder + NewRequest) — user picks.
- Helper constructors may panic on bad args ("NewRequest panics on error for ease of use in testing").
- Human escape hatches: -httptest.serve blocks the server for manual poking; cmd/go -testwork preserves script workdirs.
- Harnesses are themselves tested: TestNewClientServerTest (clientserver_test.go:362), TestTestClientConn — the harness self-test doubles as its usage documentation.
- Matrix runners keep one test body across variants: run(t, f, modes) over HTTP/1/2/3 (generic over TBRun so tests and benchmarks share it); database/sql's testDatabase runs f against drivers implementing different optional-interface sets, filtered by requireFeature("Validator") options; options passed as ...any with a type switch, unknown type = t.Fatalf.

## Contract-verifier doctrine (fstest/iotest/slogtest)
- Shape: func TestX(impl, expectations...) error — takes NO *testing.T, joins all violations (errors.Join), caller t.Fatal(err). slogtest adds the subtest-shaped Run(t, ...) as a second entry point.
- Verifier + fake pair in one package: TestFS + MapFS; TestReader + adversarial wrappers. Fakes verify consumers; verifiers verify producers.
- Verifiers probe optional capabilities by type assertion and test them only if present (TestReader: Seeker/ReaderAt; TestFS: ReadLinkFS).
- Adversarial wrappers get used as a table: bufio's readMakers = {full, byte, half, data+err, timeout} runs every reader test 5 ways (bufio_test.go:84-90).
- Versioning: verifiers only tighten (TestFS gained symlink checks, multi-error), deliberately breaking lagging implementations — the tightened verifier IS the flagged breaking change. Fakes only grow richer. Helper mistakes are never removed: ResponseRecorder.HeaderMap is "Deprecated: ... exists for historical compatibility" with Result() added beside it; NewServer stays while docs say "Most users should use NewTestServer instead". Experimental API (synctest.Run under GOEXPERIMENT) was renamed/removed before stabilizing as Test.

## txtar mechanics and why it beats one-file-per-fixture
- Format: optional comment, then "-- name --" file sections; Parse cannot fail; trailing newlines normalized; goals per doc: hand-editable, stores file trees for test cases, diffs nicely in git.
- Golden multi-view pattern (go/doc/comment/testdata_test.go:50-92): archive comment = JSON config unmarshaled into the Printer; file "input" = source; remaining files = named expected outputs (dump/gofmt/html/markdown/text) all rendered from ONE parse and compared with internal/diff. One fixture exercises parser + every renderer together — exactly "fewer tests, more API per test". `$\n -> \n` strip protects trailing-space expectations from editors.
- Script pattern (cmd/go/script_test.go:98-166): comment = the script, files = initial workdir via State.ExtractFiles; per-file t.Run parallel subtests; -testsum rewrites the archive in place when tests pass (fixture auto-amendment via txtar.Format).
- One case = one reviewable file holding input AND expectations; contract changes appear as atomic diffs; archives are programmatically rewritable, enabling -update/-fixreadme flows.

## io-interfaces vs disk contrast
- bufio (no disk ever): consumes io.Reader; tests use strings.Reader/bytes.Buffer plus the iotest wrapper matrix; contract-consumption tested under pathological readers.
- os (real disk, justified): the filesystem IS the contract; tests use t.TempDir()/t.Chdir throughout — and still verify os.DirFS with fstest.TestFS(fsys, "a", "b", "dir/x") (os_test.go:3356), i.e. even the disk-bound package validates its abstract fs.FS view with the shared verifier.
- Rule: disk appears in tests only when disk is the contract; otherwise take io/fs interfaces and test in memory.

## CLI script tests + x-module patterns

## 1. Anatomy of a cmd/go script test (go/src/cmd/go)

One file in testdata/script/*.txt is a txtar archive with two halves: the comment section (everything before the first `-- name --` marker) is the SCRIPT; the file sections are the FIXTURE TREE, extracted into a fresh per-test $WORK before execution (script starts in $WORK/gopath/src, HOME=/no-home, GOPROXY pointing at a local proxy — fully hermetic, t.Parallel per file). 925 such files exist today.

Script language (cmd/internal/script, ~2,474 lines: engine/state/cmds/conds/errors + scripttest adapter): one command per line; env-var expansion; `#` comments delimit PHASES (failure output shows only the failing phase's transcript, earlier phases collapse to their headings with timings); `!` prefix = command must fail; `?` = indifferent; `[cond]`/`[!cond]` guards ([short], [git], [GOOS:windows], [exec:bash]...). Assertions ARE commands: `stdout 'regex'`, `stderr -count=1 'regex'`, `grep`, `cmp file1 file2` (file1 may literally be `stdout`/`stderr`; goldens are just more txtar sections), `cmpenv`, `exists`, `! stdout .` (stream empty). $WORK paths are rewritten symbolically in failure output; `-testwork` preserves the tree for manual debugging; the failing script file:line is reported so editors jump to the .txt.

Harness tricks worth stealing: (a) TestMain re-executes the TEST BINARY ITSELF as the `go` command via CMDGO_TEST_RUN_MAIN (go_test.go:101) — zero build step, coverage flows; (b) `-testsum tidy` REWRITES the script's own go.mod/go.sum txtar sections in place — scripts are machine-maintainable fixtures; (c) testdata/script/README is generated from the engine's self-documenting Cmd/Cond usage structs (scriptreadme_test.go), so docs cannot drift; (d) heavyweight infrastructure (module proxy in proxy_test.go, vcs-test server) is built ONCE in Go and exposed to all scripts via env; (e) per-command customization is a map entry: scriptcmds_test.go registers `go`, `cc`, `stale`; conds add `[cgo]`, `[net:*]`.

Why superior to Go-code e2e for a CLI: the test is a transcript of exactly the user-observable contract — argv, cwd, env, exit status, two streams — and can assert nothing else (a Go test can quietly reach into internals; a script physically cannot). Fixture locality: the broken source file sits ten lines above the `stderr 'file.sdl:3:8: ...'` assertion, so positions are checkable by eye instead of hand-counting lines inside a Go backtick string at helper-call distance. Marginal cost of case N+1 is one small text file: no compilation, no helper naming, no t.Fatalf boilerplate; failure reporting is uniform. And it keeps CLI-artifact tests OUT of library packages: libraries assert their Go API to sibling users, the corpus asserts the shell-level contract.

## 2. When the Go project still writes Go-code CLI tests

- go_test.go keeps ~57 legacy tests (pre-2018 testgo framework; the bulk was migrated to scripts). What stayed needs programmatic assertions: binary/symbol inspection (TestUpxCompression, TestDuplicateGlobalAsmSymbols), structured loops over output, platform probing.
- terminal_test.go (PTY passthrough), chdir_test.go, note_test.go: process-level semantics a script language cannot express.
- Infrastructure consumed by scripts (proxy, vcstest, telemetry counter checks around each script) is Go.
- Rule extracted: if a shell user can observe it → script; if the assertion needs Go types or fd/signal choreography → Go test; if it is setup → Go infrastructure exposed via env or a custom script command.

## 3. cmd/gofmt: the in-process golden-pair pattern (no binary at all)

gofmt_test.go is package `main` (not main_test) and never executes the gofmt binary: it calls processFile/newSequencer in-process against testdata/*.input → *.golden pairs. Per-fixture flags ride INSIDE the fixture as a `//gofmt -r=x->y` comment (first 20 lines); `-update` rewrites goldens; each golden is re-run through the formatter to prove idempotence (`runTest(t, out, out)`); on failure the got-bytes are written beside the input as `.gofmt` for inspection; gofmt.go itself is added to the corpus as a large example. go/printer is the same with a Go-side table binding input→golden plus mode bits (one input, several goldens under different modes). go/parser puts expectations inside fixtures as `/* ERROR "rx" */` immediately after the offending token — the comment's own position defines the expected error position (error_test.go:67).

## 4. analysistest (x/tools go/analysis/analysistest): expectations beside fixtures

Fixture = real, compilable packages under testdata (or a WriteFiles map → GOPATH tree). Run loads with go/packages, applies the analyzer, then checks `// want "regex"` comments ON the offending line — the comment's position IS the expected diagnostic position; facts as `name:"factRx"`. Sealing is bidirectional: unmatched expectations AND unexpected diagnostics both fail. Suggested fixes compare against `file.go.golden` beside the fixture; when one diagnostic offers several fixes the golden is a txtar archive with one section per fix message. Doctrine: each compiler layer gets a bespoke few-hundred-line harness, written once, that turns that layer's user contract into a corpus with in-fixture expectations — the harness IS a driver, i.e. the layer exercised as its user. Parser → ERROR comments; analyzer → want comments; CLI → script transcripts.

## 5. Our cmd/sdl suite, measured against this

Inventory: cmd/sdl/e2e_test.go 2,066 lines / 26 tests; run_e2e_test.go 206; completion_e2e_test.go 107; TestMain `go build`s the binary once. ### Recommendations

- Migrate PARTIALLY, not wholly, and let the boundary be observability: a case moves to a script only if a shell user could verify it (argv, cwd, env, exit code, streams, files); anything asserting through image.Decode/image.Equal or Go types stays a Go test. cmd/go itself is the precedent: 925 scripts AND 57 Go-code tests AND Go-built infrastructure coexisting.
- Move the diagnostics corpus first — TestDiagnostics, TestSymbolDiagnostics, TestProvisionDiagnostics, TestSchemeChecking/ImportedSchemeChecks, PerFileImportScope/ForgottenImport, TestRunUnboundExtern/Sample/CompileFault — plus the pure stream/exit tests (TestBuildStdout, TestBuildDeterminism, TestFmtExamples, TestBuildOutputDevice, TestBuildOutputAtomic, TestBuildVendored, the -generation usage fault). These become cmd/sdl/testdata/script/*.txt where the broken .sdl unit is a visible file section and 'stderr \'broken.sdl:8:18: ...\'' sits beside it — line:col checkable by eye instead of hand-counted inside Go backtick strings. This is also where every future language feature adds cases, so the corpus format pays compounding rent.
- Keep the round-trip family (RoundTripEcho/Symbols/Provisions/Defaults/Compartments/Sample, FactoredForms), TestRunPingpong's signal choreography, TestBuildPingpong/TestBuildSample's deep decode asserts, and the workspace/proxy tests in Go. image.Equal IS the committed contract of the image package exercised as its user; transcribing it into scripts would mean growing CLI surface (an 'image equal' verb) just to serve tests — inverted priorities. Do NOT add CLI verbs for testability unless operators independently want them.
- For the engine, prefer github.com/rogpeppe/go-internal/testscript over a bespoke runner: one dependency (already in your module cache at v1.14.1), and invoke() is already RunMain-shaped, so testscript.Main(m, map[string]func() int{"sdl": ...}) re-executes the test binary as sdl — this DELETES the go-build step in TestMain and gives UpdateScripts (subsumes your hand-rolled -update for cmp goldens), TestWork, [short]/[exec:*] conditions, and phase-collapsed failure transcripts for free. x/tools txtar alone buys only the fixture format; the assertion language, quoting, conds, and update mode are the real cost, and cmd/go needed 2.5k lines for them.
- If the no-new-dependency instinct wins (legitimate at prototype grade), the halfway house is a ~200-line bespoke runner over x/tools txtar supporting exactly: file extraction to t.TempDir, `sdl args...` (delegating to the existing runSDL), `!` inversion, `stdout/stderr 'regex'`, `cmp`, `exists`. Record the reopening trigger where it will be found: the day a script needs conditions, env expansion, or background commands, switch to testscript rather than grow the engine.
- Steal cmd/go's infrastructure pattern for hermeticity: keep writeProxy/hermeticProxyEnv as Go code and expose them to scripts via env (GOPROXY=file://...) set once in the harness — scripts consume infrastructure, they never build it.
- Adopt gofmt's idempotence trick in the fmt path if not already present at the package level: after any golden comparison of formatted output, re-run the formatter on the golden and demand a fixed point ('runTest(t, out, out)'); it is the cheapest strong property a formatter contract can pin.
- Longer-term door to keep visibly open: your sdl/parser and future analyzers deserve the analysistest doctrine — a bespoke per-layer harness where expectations live beside fixtures at line granularity (go/parser's /* ERROR "rx" */ or analysistest's // want). The e2e diagnostics scripts test the CLI's rendering of positions; an in-fixture ERROR-comment corpus at the parser/linker layer would test the positions themselves without booting the toolchain, and is a few hundred lines written once.

(b) lspcmd runLsp (lsp.go:122–145): the interrupt lever (io.Pipe pump goroutine + context.AfterFunc over os.Stdin) sits ABOVE the tested serve(in,out) seam — the very behavior of commit 9c0cc73 is untested; factor runLsp into run(ctx, in, out) and the cancel-unblocks-read claim becomes a synctest one-liner; trivial cost. (c) host.Main subscribes real signals internally (signal_test.go delivers real SIGTERM to the test process, unix-tagged, 10s time.After bound; grace-deadline check is presence-only, not budget) — a Config signal-source seam (chan os.Signal) makes sequencing synctest-deterministic and portable while ONE real-SIGTERM test stays as the kernel-integration pin; one-field cost, worth it. (d) work's `go` CLI and fmt/vet/load disk coupling: do NOT seam — the toolchain/filesystem IS the contract there; t.TempDir and e2e are the honest levels. (e) HTTPServer needs either a Serve(net.Listener) form or just a readiness dial; the 1s sleep is pure flake-tax, no redesign required.

**(9) Sleeps/real time where synctest fits:** application/httpapp_test.go:22 `time.Sleep(time.Second)` — the only true sleep; runtime_test.go already models synctest correctly (the repo knows the tool). solution/host signal tests: real time bounds only (fail-fast channels), acceptable but see 8c. run_e2e watchdog 4 min: e2e, fine. compose_test/host tests run real ff.Ping at 10ms interval count:1 — negligible.

**No-test packages:** loaderflags (contract pinned only transitively), base (partially via invoke/e2e), buildcmd/runcmd (e2e), examples/host (nowhere), root main (noop). Harness precedents: CheckDescriptor/CheckProvisionType/CheckSchemeType all `testing.TB` + self-tested accept/reject suites (failer pattern duplicated verbatim in application and solution — necessary, no shared home); CheckParser breaks all three conventions (untested, uncalled, *testing.T). All four harnesses live in the production package importing "testing" — deliberate single-import ergonomics for catalogue citizens, at the cost of linking testing into every consumer binary.

## RANKED VERDICT
**Most need remastering:** 1) application (scaffolds, sleep, kind-sweep bloat, ~9 untested exports) — needs API pruning FIRST; 2) loaderflags (zero tests on a load-bearing contract + dead harness); 3) cmd/sdl e2e (deduplicate linker pins, extract round-trip helper); 4) application/parameter + sdl/token (grain consolidation); 5) root main (delete); 6) base (in-process exit-mapping + help tests); 7) examples/host (either a smoke build+run or an explicit "demo, unpinned" note).

- Prune application's speculative surface before writing any new tests for it: ShutdownSignal, ParseFromArgs/ParseFromEnvs, ParamParser/ParseTo, Loop/LoopCount, Terminate, and HealthChecker have no in-repo users outside the package (ShutdownSignal only in a downstream test double) and no tests; delete what the prototype doesn't need, and pin what survives — an untested export is a contract nobody promised.

- Replace new_reflect_test.go with one ~20-line contract test: MakeFor returns a fresh Service pointing at a zero T whose Flags pass through — two kinds (a scalar, a composite) prove the reflection claim; the 23-kind sweep, the 46 stub methods, the check-manually Logfs, and the TODO(@claude) go. - Fix httpapp_test.go: drop the commented-out t.Skip, replace the 1s sleep with a readiness dial against the bound address (or run the whole thing under synctest with a stub Runner); while there, either make BenchmarkGo assert something (allocs ceiling) or delete it. Delete root main.go/main_test.go outright — the module root needs no placeholder command.
- De-duplicate the CLI e2e against the solution suite: keep ONE representative positioned-diagnostic e2e case (proving stderr plumbing through the generated compiler) and delete the wording re-assertions that mirror TestMainCompileDiagnostics/SchemeChecking/PerFileImports rows — today a diagnostic reword forces synchronized edits in solution, e2e, and vetcmd, and only vetcmd's copy has a stated reason to shadow.
